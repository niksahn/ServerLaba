## 🎯 Основная функциональность

### Круговые диаграммы распределения запросов

Для каждого сервиса (App, User, Auth) показывается **процентное распределение запросов** между подами:

```
App Service:
├─ servers-app-1:8080 → 33%
├─ servers-app-2:8080 → 33%
└─ servers-app-3:8080 → 34%
```

Это позволяет визуально оценить, насколько равномерно Nginx распределяет нагрузку.

### Временные графики

- **RPS по подам** - показывает динамику запросов к каждому поду
- **Response Time по подам** - показывает время ответа каждого пода
- **CPU/Memory Usage** - показывает нагрузку на ресурсы


## 🔧 Технические детали

### Как это работает

1. **Nginx** записывает в логи информацию о том, на какой upstream сервер был направлен запрос (`upstream_addr`)
2. **Telegraf** парсит логи и экспортирует метрики в формате Prometheus
3. **Prometheus** собирает метрики от Telegraf
4. **Grafana** визуализирует метрики в виде круговых диаграмм и графиков

### Ключевые метрики

```promql
# Распределение запросов по подам
sum by (upstream_addr) (increase(nginxlog_resp_bytes_count{request=~".*app-service.*"}[5m]))

# RPS по подам
rate(nginxlog_resp_bytes_count{request=~".*app-service.*", upstream_addr=~".*"}[5m])

# CPU usage подов
rate(container_cpu_usage_seconds_total{namespace="microservices-lab", pod=~"servers-app-.*"}[5m])
```

## 🎯 Примеры использования

### Проверка балансировки Round Robin

1. Запустите нагрузочный тест
2. Откройте дашборд
3. Посмотрите на круговую диаграмму App Service
4. Вы должны увидеть примерно равное распределение (33%/33%/33%)

### Сравнение алгоритмов балансировки

```bash
# Round Robin
./k8s/tools/switch-nginx-algorithm.sh round-robin
# Наблюдайте: равномерное распределение

# Least Connections
./k8s/tools/switch-nginx-algorithm.sh least-connections
# Наблюдайте: распределение зависит от нагрузки

# IP Hash
./k8s/tools/switch-nginx-algorithm.sh ip-hash
# Наблюдайте: неравномерное распределение (один клиент → один сервер)
```

### Поиск проблем с производительностью

1. Посмотрите на графики времени ответа
2. Если один под медленнее других:
   - Проверьте CPU/Memory usage
   - Проверьте логи пода
   - Возможно, под перегружен

## ❓ FAQ

**Q: Дашборд пустой, нет данных**  
A: Запустите нагрузочный тест для генерации трафика

**Q: Метрики не обновляются**  
A: Проверьте логи Telegraf и убедитесь, что Nginx перезапущен

**Q: Неравномерное распределение при Round Robin**  
A: Проверьте, что все поды в состоянии Ready

**Q: Как переключить алгоритм балансировки?**  
A: Используйте скрипт `switch-nginx-algorithm.sh`
